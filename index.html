Field guide · objects, YAML & Helm charts

Every object in the cluster, laid out on the deck.

Kubernetes takes its name from the Greek word for helmsman. This is the manifest for the ship: every core object with working YAML, plus the full anatomy of a Helm chart — folder by folder, file by file.

Pod

core/v1

The smallest deployable unit. One or more containers that share a network namespace and storage volumes, scheduled together onto the same node, living and dying together.

Scope
Namespaced
Managed by
Usually a controller
Restart policy
Always / OnFailure / Never
Typical use
Debugging, one-offs
pod.yaml
apiVersion: v1
kind: Pod
metadata:
  name: web-pod
  namespace: default
  labels:
    app: web
    tier: frontend
spec:
  containers:
    - name: web
      image: nginx:1.27-alpine
      ports:
        - containerPort: 80
      resources:
        requests:
          cpu: "100m"
          memory: "128Mi"
        limits:
          cpu: "250m"
          memory: "256Mi"
      livenessProbe:
        httpGet:
          path: /healthz
          port: 80
        initialDelaySeconds: 5
        periodSeconds: 10
      volumeMounts:
        - name: cache-volume
          mountPath: /var/cache/nginx
  volumes:
    - name: cache-volume
      emptyDir: {}
  restartPolicy: Always
In production, you almost never create bare Pods directly — a Deployment or StatefulSet creates and supervises them for you.

ReplicaSet

apps/v1

Keeps a stable number of identical Pods running. Rarely written by hand — a Deployment generates and owns one for you on every rollout.

replicaset.yaml
apiVersion: apps/v1
kind: ReplicaSet
metadata:
  name: web-rs
  labels:
    app: web
spec:
  replicas: 3
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
        - name: web
          image: nginx:1.27-alpine
          ports:
            - containerPort: 80

Deployment

apps/v1

The workhorse. Declares a desired state for stateless Pods and rolls changes out gradually, with rollback built in. Owns a ReplicaSet, which owns the Pods.

deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web-deployment
  labels:
    app: web
spec:
  replicas: 4
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
        - name: web
          image: myregistry/web:1.4.2
          ports:
            - containerPort: 8080
          envFrom:
            - configMapRef:
                name: web-config
          resources:
            requests: { cpu: "150m", memory: "192Mi" }
            limits: { cpu: "500m", memory: "384Mi" }
          readinessProbe:
            httpGet: { path: /ready, port: 8080 }
            initialDelaySeconds: 3
Rollout in one line: kubectl rollout undo deployment/web-deployment reverts to the prior ReplicaSet if a release goes bad.

StatefulSet

apps/v1

For workloads that need stable identity: a fixed name, a fixed network address, and a dedicated volume per replica that survives rescheduling. Databases, brokers, anything with "which one am I" logic.

statefulset.yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: pg
spec:
  serviceName: "pg-headless"
  replicas: 3
  selector:
    matchLabels:
      app: pg
  template:
    metadata:
      labels:
        app: pg
    spec:
      containers:
        - name: postgres
          image: postgres:16-alpine
          ports:
            - containerPort: 5432
              name: db
          env:
            - name: POSTGRES_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: pg-secret
                  key: password
          volumeMounts:
            - name: data
              mountPath: /var/lib/postgresql/data
  volumeClaimTemplates:
    - metadata:
        name: data
      spec:
        accessModes: ["ReadWriteOnce"]
        storageClassName: fast-ssd
        resources:
          requests:
            storage: 20Gi
Pods get names pg-0, pg-1, pg-2 — created and scaled down in that strict order, each bound to its own PersistentVolumeClaim.

DaemonSet

apps/v1

Runs exactly one copy of a Pod on every (or every matching) node. The default choice for log shippers, node monitoring agents, and CNI plugins.

daemonset.yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: node-log-agent
spec:
  selector:
    matchLabels:
      app: log-agent
  template:
    metadata:
      labels:
        app: log-agent
    spec:
      tolerations:
        - effect: NoSchedule
          operator: Exists
      containers:
        - name: fluentbit
          image: fluent/fluent-bit:3.0
          volumeMounts:
            - name: varlog
              mountPath: /var/log
              readOnly: true
      volumes:
        - name: varlog
          hostPath:
            path: /var/log

Job

batch/v1

Runs Pods to completion. Once the specified number finish successfully, the Job is done — no restart, no rescheduling.

job.yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: db-migrate
spec:
  backoffLimit: 3
  completions: 1
  template:
    spec:
      containers:
        - name: migrate
          image: myregistry/migrator:2.1
          command: ["./migrate", "up"]
      restartPolicy: Never

CronJob

batch/v1

Schedules a Job on a cron expression — nightly backups, hourly reports, periodic cleanup.

cronjob.yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: nightly-backup
spec:
  schedule: "0 2 * * *"
  concurrencyPolicy: Forbid
  jobTemplate:
    spec:
      template:
        spec:
          containers:
            - name: backup
              image: myregistry/backup-tool:1.0
              args: ["--target", "s3://backups/nightly"]
          restartPolicy: OnFailure

ConfigMap

core/v1

Non-secret configuration as key-value pairs, injected as environment variables or mounted as files — kept separate from the container image.

configmap.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: web-config
data:
  LOG_LEVEL: "info"
  FEATURE_FLAG_NEW_UI: "true"
  nginx.conf: |
    server {
      listen 80;
      location /healthz { return 200; }
    }

Secret

core/v1

Like a ConfigMap, but for sensitive values — base64-encoded at rest, and only decoded when mounted into a Pod. Base64 is encoding, not encryption; pair it with a KMS-backed provider or sealed-secrets for real protection.

secret.yaml
apiVersion: v1
kind: Secret
metadata:
  name: pg-secret
type: Opaque
data:
  username: cG9zdGdyZXM=   # base64 for "postgres"
  password: c3VwZXJzZWNyZXQ=
Never commit real Secret manifests to version control. Use --dry-run=client -o yaml, a sealed-secrets controller, or an external secrets operator instead.

PersistentVolume

core/v1

A piece of storage in the cluster, provisioned by an admin or dynamically by a StorageClass — a resource that outlives any single Pod.

pv.yaml
apiVersion: v1
kind: PersistentVolume
metadata:
  name: pv-data-01
spec:
  capacity:
    storage: 20Gi
  accessModes:
    - ReadWriteOnce
  persistentVolumeReclaimPolicy: Retain
  storageClassName: fast-ssd
  hostPath:
    path: /mnt/disks/data01

PersistentVolumeClaim

core/v1

A request for storage by a Pod — binds to a matching PersistentVolume, or triggers dynamic provisioning through a StorageClass.

pvc.yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: web-uploads
spec:
  accessModes:
    - ReadWriteOnce
  storageClassName: fast-ssd
  resources:
    requests:
      storage: 5Gi

StorageClass

storage.k8s.io/v1

A named "profile" for dynamic provisioning — which storage backend to use, and how, so PersistentVolumeClaims don't need to know the details.

storageclass.yaml
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: fast-ssd
provisioner: kubernetes.io/aws-ebs
parameters:
  type: gp3
  fsType: ext4
reclaimPolicy: Delete
volumeBindingMode: WaitForFirstConsumer

Service

core/v1

A stable network identity and load balancer in front of a shifting set of Pods, matched by label selector. Three shapes cover most cases.

service-clusterip.yaml
apiVersion: v1
kind: Service
metadata:
  name: web-svc
spec:
  type: ClusterIP        # internal only — the default
  selector:
    app: web
  ports:
    - port: 80
      targetPort: 8080
service-nodeport.yaml
apiVersion: v1
kind: Service
metadata:
  name: web-svc-nodeport
spec:
  type: NodePort         # exposes a port on every node
  selector:
    app: web
  ports:
    - port: 80
      targetPort: 8080
      nodePort: 30080
service-loadbalancer.yaml
apiVersion: v1
kind: Service
metadata:
  name: web-svc-lb
spec:
  type: LoadBalancer     # provisions a cloud load balancer
  selector:
    app: web
  ports:
    - port: 443
      targetPort: 8080

Ingress

networking.k8s.io/v1

HTTP(S) routing rules from outside the cluster to internal Services — host and path based, usually with TLS termination. Requires an Ingress controller to actually do anything.

ingress.yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: web-ingress
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /
spec:
  ingressClassName: nginx
  tls:
    - hosts: ["app.example.com"]
      secretName: app-tls
  rules:
    - host: app.example.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: web-svc
                port:
                  number: 80

NetworkPolicy

networking.k8s.io/v1

Firewall rules for Pod-to-Pod traffic. Without any policy, all Pods can reach all Pods — this locks that down to an explicit allow-list.

networkpolicy.yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-web-to-db
spec:
  podSelector:
    matchLabels:
      app: pg
  policyTypes: ["Ingress"]
  ingress:
    - from:
        - podSelector:
            matchLabels:
              app: web
      ports:
        - protocol: TCP
          port: 5432

ServiceAccount

core/v1

An identity a Pod uses when talking to the API server — the "who" that RBAC rules attach to.

serviceaccount.yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: web-runner
  namespace: default

Role & RoleBinding

rbac.authorization.k8s.io/v1

A Role lists permitted verbs on resources, scoped to one namespace. A RoleBinding grants that Role to a user, group, or ServiceAccount.

role.yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  namespace: default
  name: pod-reader
rules:
  - apiGroups: [""]
    resources: ["pods"]
    verbs: ["get", "list", "watch"]
rolebinding.yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: read-pods-binding
  namespace: default
subjects:
  - kind: ServiceAccount
    name: web-runner
    namespace: default
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io

ClusterRole & ClusterRoleBinding

rbac.authorization.k8s.io/v1

Same idea as Role/RoleBinding, but cluster-wide — for cluster-scoped resources like Nodes, or permissions that apply across every namespace.

clusterrole.yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: node-viewer
rules:
  - apiGroups: [""]
    resources: ["nodes"]
    verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: node-viewer-binding
subjects:
  - kind: ServiceAccount
    name: web-runner
    namespace: default
roleRef:
  kind: ClusterRole
  name: node-viewer
  apiGroup: rbac.authorization.k8s.io

Namespace

core/v1

A virtual partition of the cluster — scopes names, quotas, and RBAC so multiple teams or environments can share one cluster without colliding.

namespace.yaml
apiVersion: v1
kind: Namespace
metadata:
  name: staging
  labels:
    env: staging

ResourceQuota

core/v1

Caps the total compute and object counts a namespace can consume — the guardrail that stops one team from starving the rest of the cluster.

resourcequota.yaml
apiVersion: v1
kind: ResourceQuota
metadata:
  name: staging-quota
  namespace: staging
spec:
  hard:
    requests.cpu: "4"
    requests.memory: 8Gi
    limits.cpu: "8"
    limits.memory: 16Gi
    pods: "20"

LimitRange

core/v1

Sets default and min/max compute requests per container within a namespace — so a Pod that forgets to set resources doesn't get scheduled unbounded.

limitrange.yaml
apiVersion: v1
kind: LimitRange
metadata:
  name: default-limits
  namespace: staging
spec:
  limits:
    - type: Container
      default:
        cpu: "250m"
        memory: "256Mi"
      defaultRequest:
        cpu: "100m"
        memory: "128Mi"
      max:
        cpu: "1"
        memory: "1Gi"

HorizontalPodAutoscaler

autoscaling/v2

Watches a metric — usually CPU or memory utilization — and adjusts the replica count on a Deployment or StatefulSet to match.

hpa.yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: web-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: web-deployment
  minReplicas: 2
  maxReplicas: 10
  metrics:
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization
          averageUtilization: 65
Package manager for Kubernetes

Helm — the actual ship's wheel

Helm packages a set of YAML manifests into a versioned, templated, installable unit called a chart. Instead of hand-editing a dozen files per environment, you fill in one values.yaml and Helm renders the rest.

Chart folder structure

helm create mychart

Every chart follows the same skeleton. Helm's own scaffolding command produces exactly this layout.

mychart/ ├── Chart.yaml # chart metadata: name, version, appVersion ├── values.yaml # default configuration values ├── values.schema.json # optional — validates values.yaml ├── .helmignore # patterns excluded when packaging ├── charts/ # subcharts / vendored dependencies ├── templates/ # Kubernetes manifests, templated │ ├── deployment.yaml │ ├── service.yaml │ ├── ingress.yaml │ ├── configmap.yaml │ ├── serviceaccount.yaml │ ├── hpa.yaml │ ├── _helpers.tpl # reusable named templates │ ├── NOTES.txt # post-install usage message │ └── tests/ │ └── test-connection.yaml └── crds/ # CustomResourceDefinitions, applied first
Anything under templates/ is run through Go's templating engine before being sent to the API server. Everything else — Chart.yaml, charts/, crds/ — is not templated.

Chart.yaml

metadata

Identity and version info for the chart itself — separate from the version of the application it deploys.

Chart.yaml
apiVersion: v2
name: mychart
description: A Helm chart for the web application
type: application
version: 1.4.0          # chart version — bump on any template change
appVersion: "1.2.3"      # version of the app being deployed
kubeVersion: ">=1.25.0-0"
keywords:
  - web
  - api
maintainers:
  - name: Platform Team
    email: platform@example.com
dependencies:
  - name: redis
    version: "18.x.x"
    repository: "https://charts.bitnami.com/bitnami"
    condition: redis.enabled

values.yaml

defaults

The single file most people edit per environment. Every value here is reachable in templates as .Values.<path>.

values.yaml
replicaCount: 3

image:
  repository: myregistry/web
  tag: "1.4.2"
  pullPolicy: IfNotPresent

serviceAccount:
  create: true
  name: ""

service:
  type: ClusterIP
  port: 80
  targetPort: 8080

ingress:
  enabled: true
  className: nginx
  host: app.example.com
  tls: true

resources:
  requests:
    cpu: 150m
    memory: 192Mi
  limits:
    cpu: 500m
    memory: 384Mi

autoscaling:
  enabled: true
  minReplicas: 2
  maxReplicas: 10
  targetCPUUtilizationPercentage: 65

redis:
  enabled: false
Override any of it at install time without touching the file: helm install web ./mychart --set image.tag=1.4.3 --set replicaCount=5

templates/

rendered manifests

Ordinary Kubernetes YAML with Go template expressions dropped in. Helm renders every file here against values.yaml before applying it.

templates/deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ include "mychart.fullname" . }}
  labels:
    {{- include "mychart.labels" . | nindent 4 }}
spec:
  {{- if not .Values.autoscaling.enabled }}
  replicas: {{ .Values.replicaCount }}
  {{- end }}
  selector:
    matchLabels:
      {{- include "mychart.selectorLabels" . | nindent 6 }}
  template:
    metadata:
      labels:
        {{- include "mychart.selectorLabels" . | nindent 8 }}
    spec:
      serviceAccountName: {{ include "mychart.serviceAccountName" . }}
      containers:
        - name: {{ .Chart.Name }}
          image: "{{ .Values.image.repository }}:{{ .Values.image.tag | default .Chart.AppVersion }}"
          imagePullPolicy: {{ .Values.image.pullPolicy }}
          ports:
            - containerPort: {{ .Values.service.targetPort }}
          resources:
            {{- toYaml .Values.resources | nindent 12 }}
templates/service.yaml
apiVersion: v1
kind: Service
metadata:
  name: {{ include "mychart.fullname" . }}
spec:
  type: {{ .Values.service.type }}
  ports:
    - port: {{ .Values.service.port }}
      targetPort: {{ .Values.service.targetPort }}
  selector:
    {{- include "mychart.selectorLabels" . | nindent 4 }}
templates/ingress.yaml
{{- if .Values.ingress.enabled }}
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: {{ include "mychart.fullname" . }}
spec:
  ingressClassName: {{ .Values.ingress.className }}
  {{- if .Values.ingress.tls }}
  tls:
    - hosts: [{{ .Values.ingress.host }}]
      secretName: {{ include "mychart.fullname" . }}-tls
  {{- end }}
  rules:
    - host: {{ .Values.ingress.host }}
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: {{ include "mychart.fullname" . }}
                port:
                  number: {{ .Values.service.port }}
{{- end }}
templates/hpa.yaml
{{- if .Values.autoscaling.enabled }}
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: {{ include "mychart.fullname" . }}
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: {{ include "mychart.fullname" . }}
  minReplicas: {{ .Values.autoscaling.minReplicas }}
  maxReplicas: {{ .Values.autoscaling.maxReplicas }}
  metrics:
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization
          averageUtilization: {{ .Values.autoscaling.targetCPUUtilizationPercentage }}
{{- end }}
templates/NOTES.txt
Chart "{{ .Chart.Name }}" installed as release "{{ .Release.Name }}".

Check status with:
  kubectl get pods -l app.kubernetes.io/instance={{ .Release.Name }}

{{- if .Values.ingress.enabled }}
Visit: https://{{ .Values.ingress.host }}
{{- else }}
Forward a local port to reach it:
  kubectl port-forward svc/{{ include "mychart.fullname" . }} 8080:{{ .Values.service.port }}
{{- end }}

_helpers.tpl

shared named templates

Reusable snippets, defined once with define and pulled into any template with include — the DRY layer of a chart.

templates/_helpers.tpl
{{- define "mychart.fullname" -}}
{{- printf "%s-%s" .Release.Name .Chart.Name | trunc 63 | trimSuffix "-" -}}
{{- end -}}

{{- define "mychart.labels" -}}
app.kubernetes.io/name: {{ .Chart.Name }}
app.kubernetes.io/instance: {{ .Release.Name }}
app.kubernetes.io/version: {{ .Chart.AppVersion }}
helm.sh/chart: {{ .Chart.Name }}-{{ .Chart.Version }}
{{- end -}}

{{- define "mychart.selectorLabels" -}}
app.kubernetes.io/name: {{ .Chart.Name }}
app.kubernetes.io/instance: {{ .Release.Name }}
{{- end -}}

{{- define "mychart.serviceAccountName" -}}
{{- if .Values.serviceAccount.create -}}
{{ default (include "mychart.fullname" .) .Values.serviceAccount.name }}
{{- else -}}
{{ default "default" .Values.serviceAccount.name }}
{{- end -}}
{{- end -}}

Subcharts & dependencies

charts/

A chart can depend on other charts — declared in Chart.yaml, vendored into charts/, and configured from the parent's values.yaml under the dependency's own name.

mychart/ ├── Chart.yaml # lists "redis" under dependencies ├── values.yaml # has a top-level "redis:" block └── charts/ └── redis/ # pulled in by `helm dependency update` ├── Chart.yaml ├── values.yaml └── templates/
values.yaml (parent, passing config down)
redis:
  enabled: true
  auth:
    enabled: true
    existingSecret: pg-secret
  master:
    persistence:
      size: 8Gi
Run helm dependency update ./mychart to download declared dependencies into charts/ as .tgz archives before packaging or installing.
